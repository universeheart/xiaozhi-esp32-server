# AI 陪伴机器人一期开发计划

> 历史说明：本计划的固定周历已于 2026-08-22 被《开发执行计划-v0.4.md》替代；本文仅保留里程碑和传统两人团队工作量参考。

> 版本：v0.3  
> 日期：2026-08-21  
> 团队：2 名研发；硬件/ESP32 外包。  
> 目标：完成 50 台功能丰富试产样品的软件基线。  
> 建议周期：26 周开发与内部验证 + 2 周试产缓冲，共 28 周。若 MTK/ESP32 接口首月无法提供，最终日期顺延。

## 1. 人员主责

| 人员 | 主责 | 辅责 |
|---|---|---|
| 开发 A | Python 实时服务、Java manager-api、数据、模型/LINE、部署 | uni-app 家属端、服务测试 |
| 开发 B | Flutter 机器人端、Kotlin 设备层、音频、本地唤醒、ESP32 通信 | 表情 UI、Android 测试 |
| 共同 | 协议、架构评审、端到端测试、发布与试产问题 | 文档和验收证据 |

两人团队不能同时全面开发三类客户端。家属 App 必须裁剪现有 `manager-mobile`，机器人端继续使用现有 Flutter 项目；不得另起原生 iOS/Android 两套工程。

## 3. 两周迭代计划

### Sprint 1（W1–W2）：基线、协议和安全清理

开发 A：

- 冻结 `xiaozhi-esp32-server` 基线，评审落后上游的提交并形成升级决策。
- 建开发/测试配置模板；数据库/API 密钥改为环境变量或 Secret。
- 梳理 `manager-api` 当前设备、用户、智能体、聊天记录表和接口。
- 建日本测试环境最小部署：WSS、Python 服务、manager-api、MySQL、Redis。

开发 B：

- 冻结 Android fork，清理绝对 Gradle/JDK 路径、debug release signing 和 Token/正文日志。
- 修复 PCM ring buffer/Opus 60 ms 连续分帧，建立样本守恒测试。
- 实现 WebSocket `CONNECTING/HANDSHAKING/READY/OFFLINE` 状态机。
- 建 Android—ESP32 transport 接口和 fake transport，不等待实际硬件。

共同交付：协议 schema/示例、ADR、CI 构建、SBOM、Secret 扫描。

退出条件：干净开发机/CI 可生成服务镜像和 Android APK；固定 PCM 输入无丢样本；默认测试 Token 不可能进入 Release。

### Sprint 2（W3–W4）：服务端语音 2.0 与可靠播放

开发 A：

- 对比豆包语音 2.0 与现有旧 Provider 协议，新增独立 Provider 和配置迁移。
- 建 ASR/TTS Provider 契约测试、超时和错误映射。
- 接入至少一个 LLM 基线（OpenAI-compatible 或 Gemini）并记录分段延迟。
- 增加 `traceId/sessionId/turnId/clientVersion` 日志和指标。

开发 B：

- 拆分 AudioCapture、FrameBuffer、OpusEncoder、PlaybackQueue。
- 实现下行 jitter buffer、旧轮次音频隔离、立即 abort。
- 音频焦点、录放切换、麦克风权限首次设置流程。
- 用 mock server 覆盖握手超时、断线、乱序和旧 TTS。

退出条件：日本测试环境连续 50 轮半双工对话；任意断线不假在线；旧轮次音频不播放。

### Sprint 3（W5–W6）：对话产品化 Alpha

开发 A：

- 对话文本按轮次持久化，生产音频默认不保存、测试音频开关和清理接口。
- 建模型/Prompt 版本记录和最小管理页面。
- ASR 空结果、LLM/TTS 超时、配额错误的本地化反馈。
- OpenAI/Gemini 基准框架：延迟、方言一致性、成本、数据处理地。

开发 B：

- 完整对话状态机：`IDLE/LISTENING/THINKING/SPEAKING/ABORTING/OFFLINE`。
- 网络变化监听、指数退避、有界音频队列和离线固定语音提示。
- 420×420 基础状态 UI：待机、聆听、思考、播报、网络错误。
- 开机启动/专用设备 kiosk 原型，验证 Android 14 权限路线。

退出条件：30 分钟连续对话、断网恢复和后台/息屏恢复通过；服务端可定位每段延迟。

### Sprint 4（W7–W8）：ESP32 通信与一级唤醒

开发 A：

- 设备状态数据模型区分 Android 与 ESP32；心跳/错误上报接口。
- 传感器事件和告警事件的服务端接收/幂等骨架。
- 建 ESP32 协议模拟器和协议记录工具。

开发 B：

- 实现最终物理 transport（取决于硬件方）；完成 HELLO、心跳、ACK 和故障恢复。
- 实现 `ACTIVE/STANDBY_LISTEN/SUSPENDED/WAKING` 电源状态机。
- 接入 ESP32 硬件 wake，或在硬件未到时用开发板/ADB 模拟。
- `PREPARE_SLEEP`/`wakeReady` 闭环，未确认时禁止真 suspend。

退出条件：100 次息屏唤醒、100 次 suspend 唤醒达到门槛；双方任意重启可自动恢复。

### Sprint 5（W9–W10）：Android 本地唤醒词与自动休眠

开发 A：

- 唤醒/休眠参数的设备配置 API 和灰度下发。
- 唤醒事件、误唤醒、唤醒到收音时延指标。
- 主动对话/提醒调度器骨架，统一 `Asia/Tokyo`。

开发 B：

- 选定并接入本地唤醒模型；PCM 前滚环形缓冲。
- 待机麦克风管线、唤醒提示音、误唤醒回退。
- 夜间、无人和空闲超时的自动待机/深休眠策略。
- 验证 Android 14 microphone FGS、Device Owner/系统权限方案。

退出条件：东北口音唤醒集达到候选阈值；待机音频不上传/保存；夜间和无人休眠流程通过。

### Sprint 6（W11–W12）：人设、东北方言与表情

开发 A：

- 六个人设维度、默认值、来源优先级和 Prompt 映射。
- 东北方言词表/纠错配置、方言评测集第一版。
- 情感分类和表情语义输出；Prompt 发布/回滚 API。
- 提醒 CRUD 和触发执行。

开发 B：

- 表情资源 manifest、预加载、状态/情感映射和异常降级。
- 接入用户提供表情包；适配 420×420 触摸屏。
- 设置页：音量、亮度、人设、提醒、免打扰。
- 手动中断和提醒确认交互。

退出条件：固定对话评测集上人设/方言/表情一致；Prompt 可灰度并回滚；提醒按东京时间触发。

### Sprint 7（W13–W14）：连续声源跟踪与语音打断

开发 A：

- 会话轮次关联声源 `sourceId/angle`，为多说话人策略留接口。
- VAD 慢语速参数按设备/用户下发；建立截断率报告。
- 主动对话规则：在场、免打扰、频控、夜间。

开发 B：

- DOA_EVENT 高频接收、平滑、过期和 active speaker 选择。
- TRACK_START/TARGET/STOP，与对话状态同步。
- 接入 MTK AEC/NS/AGC；验证后实现语音打断，否则保持半双工。
- 多人/低置信场景保持方向，避免机械抖动。

退出条件：连续跟踪 30 分钟无抖动/越界；慢语速 VAD 达候选门槛；AEC 报告支持是否开启语音打断的决策。

### Sprint 8（W15–W16）：账号、绑定和状态监控

开发 A：

- 主账号、声纹子用户、多家属—多设备关系和审计模型。
- 设备激活/绑定/解绑、短期设备 Token 和吊销。
- Android/ESP32 分离状态、设备影子和离线判断。
- 管理后台设备、对话、Prompt 和测试音频页面补齐。

开发 B：

- Android Keystore 设备身份、激活码和恢复出厂流程。
- 配置期望状态/报告状态同步。
- 设备状态和故障码上报；ESP32 不可用时降级。
- 机器人端本地设置与云端冲突处理。

退出条件：多对多绑定、解绑、Token 吊销、设备离线和配置冲突测试通过。

### Sprint 9（W17–W18）：家属 App

开发 A 主导、开发 B 仅提供联调：

- 裁剪 `manager-mobile`，完成登录/注册、绑定、设备列表和状态。
- 音量/亮度、人设、提醒、免打扰、主动对话和告警联系人设置。
- iOS/Android 开发包、正式签名准备、中文界面；日文隐私页面占位。
- 管理操作审计和乐观并发/最后修改提示。

退出条件：iOS/Android 真机完成绑定与所有一期设置；越权和旧配置覆盖测试通过。

### Sprint 10（W19–W20）：长期记忆与声纹实验

开发 A：

- 记忆抽取、分类、来源、置信度、检索、纠正和删除。
- 会话摘要和上下文预算；防止不同主账号/子用户记忆串用。
- 接入上游声纹能力，建立注册/识别/低置信回退流程。

开发 B：

- 语音纠正/忘记记忆的交互反馈。
- 声纹注册引导、失败/重录交互。
- 对话状态显示实际识别称呼，但不暴露声纹置信度给普通用户。

退出条件：记忆来源可追踪、可纠正/删除；跨账号泄漏测试为 0；声纹不足时不错误切换身份。

### Sprint 11（W21–W22）：LINE 告警与设置

开发 A：

- LINE Official Account、账号关联、push、webhook 验签与幂等。
- Alert 状态机、模拟传感器规则、所有绑定家属推送。
- LINE 设置白名单、确认、权限和审计；重试键与失败队列。

开发 B：

- Android 上报告警、显示告警/发送状态；本地断网缓存有界。
- 家属 App 的 LINE 关联、解除和测试通知入口。
- ESP32 模拟/真实 ALERT_EVENT 联调。

退出条件：重复告警只推一次；webhook 伪造被拒绝；家属阻止/解绑等失败可见；设置命令有审计。

### Sprint 12（W23–W24）：系统加固

- 72 h 长稳、弱网/断网、服务重启、模型供应商故障和数据库恢复。
- 权限、Secret、依赖漏洞、日志正文/Token/测试音频抽查。
- 日本部署备份、监控、告警和回滚演练。
- 1/3/5 m、电视/厨房噪声、东北慢语速、少量日语夹杂测试。
- 功耗测试：ACTIVE、STANDBY_LISTEN、SUSPENDED 各自电流和唤醒时延。

退出条件：所有 P0 自动化/实机门禁通过；S0/S1 为 0；形成 RC1。

### Sprint 13（W25–W26）：50 台试产准备

- 设备批量身份生成/注入、安装、配置和验收工具。
- 内部 5 台 → 15 台 → 50 台分批灰度；每批观察 48 h。
- 版本兼容矩阵、部署/恢复/换机/解绑/日志收集手册。
- 修复 RC 缺陷，冻结 Android、ESP32 协议、服务、Prompt 和表情资源版本。
- 整理已知问题和二期 Backlog（日本搜索、内容、运营、OTA）。

退出条件：50 台均可唯一激活、远程识别状态、回滚；7 天试运行无批量 S1。

### W27–W28：试产缓冲

只处理硬件联调、批量安装和现场阻断问题，不新增产品功能。

## 5. 工程门禁

### 每次合并

- 代码审查、lint/type-check、单元测试、Secret 扫描。
- 协议/数据库变更附兼容说明和迁移脚本。
- 新 Provider 必须通过统一契约测试。

### 每个 Sprint

- 在真实或模拟设备上演示纵向流程。
- 更新需求追踪、ADR、风险和已知问题。
- 指标与测试报告存档，不以“手动试过一次”代替验收。

### 试产发布

- Android 正式签名、服务镜像 digest、数据库 migration、Prompt/资源版本全锁定。
- 灰度、回滚、数据备份恢复和设备换机流程均演练。
- 测试环境音频全部有标识和清理记录；生产保存音频开关强制关闭。

## 6. 开发完成定义（Definition of Done）

单个工作项完成必须同时满足：

1. 代码进入项目 fork 的本地工作树并由用户按其流程手动 commit；
2. 单元/契约测试通过；涉及硬件时有实机证据；
3. 错误、超时、取消和重试路径已实现；
4. 日志和指标不泄露 Token/无授权音频；
5. 配置、接口和用户可见行为已更新文档；
6. 可回滚或有明确的向前修复方案；
7. 验收人根据本计划中的出口条件确认。

## 7. 当前不确定性对计划的影响

- 真 suspend 唤醒是板级/内核/ESP32 联合能力，不能只由 Flutter/Kotlin 任务保证。
- 豆包语音 2.0 的具体产品/API 版本、区域与数据处理政策尚未冻结，Provider 估算需在 Sprint 2 前确认。
- 声纹、全自动记忆和真实传感器告警均有误识别风险；一期可作为试验功能，但不得宣传为医疗/人身安全保证。
- 两名研发没有独立测试人员，计划已为共同测试预留约 25% 工时；若持续被临时功能占用，试产质量与日期只能二选一。
