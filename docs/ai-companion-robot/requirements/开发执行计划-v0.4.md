# AI 陪伴机器人开发执行计划

> 版本：v0.4  
> 日期：2026-08-22  
> 状态：当前执行基线，替代《开发计划-v0.3.md》的固定周历；v0.3 保留为工作量与里程碑参考。  
> 执行方式：Codex 主开发，两位人工开发协作；无试产截止日期时不制造日期承诺，以验收门逐步推进。

## 1. 工作方式

### 1.1 角色

| 角色 | 责任 |
|---|---|
| Codex（主开发） | 代码/数据库/测试/文档实现，静态与自动验证，问题诊断，进度与证据更新，提出最小外部协作请求 |
| 人工助手 A（软件/账号） | 提供云与模型账号、审批 Secret/外部服务、执行受权限限制的命令、代码提交/标签、真机安装与人工体验 |
| 人工助手 B（硬件/产品） | 对接 MTK/ESP32 外包方、收集协议和样例、物理连接与功耗/声学/运动测试、产品规则确认 |

两位人工开发可以互换；任务单记录实际执行人。Codex 不自动提交代码，不向外部团队发消息，不在没有确认的情况下改硬件协议。

### 1.2 单任务闭环

每次只让一个主任务处于 `IN_PROGRESS`：

1. **准备**：确认输入、依赖、涉及仓库和已有未提交修改；填写任务记录。
2. **实现**：只改任务范围内文件；同步更新接口/迁移/配置说明。
3. **自动验证**：执行最小测试、模块测试、静态检查或构建；失败不得标完成。
4. **人工验证**：仅在真机、账号、听感、硬件或产品判断不可替代时请求人工动作。
5. **交付**：记录变更文件、命令、结果、已知限制、回滚办法和证据路径。
6. **关门**：所有验收条件满足后标 `DONE`，再拉取下一个 `READY` 任务。

状态：`BACKLOG / READY / IN_PROGRESS / WAITING_HUMAN / VERIFYING / DONE / BLOCKED`。外部协议未返回时相关任务为 `WAITING_HUMAN`，但不阻塞可用模拟器推进的其它任务。

### 1.3 完成定义（DoD）

- 需求 ID 和验收条件明确；无隐含范围扩张。
- 代码可构建，新增逻辑有自动测试；无法自动测的原因与人工步骤已记录。
- 配置不含真实 Secret；日志不泄露 Token、完整音频和不必要的正文。
- 数据库变更含前向迁移、校验查询和补偿/回滚说明。
- 接口变更同步 schema/示例/错误码；客户端与服务端版本兼容策略明确。
- 看板和证据索引更新；人工助手能按步骤复现结论。

## 2. 验收门与任务清单

估算使用 `XS ≤0.5 天、S≈1 天、M≈2 天、L≈3–5 天`，仅用于拆分和排序；任务超过 L 必须再次拆分。编号顺序不代表必须全部串行，但一次执行一个可交付任务。

## 4. 范围和日期管理

- 新需求先进入 `BACKLOG`，补充需求/验收/依赖后再排为 `READY`；不会直接插入正在验证的任务。
- 只有试产日期、样机到达和外部账号日期确定后才计算日历排期。原 v0.3 的 26+2 周可作为两名传统全职研发的粗略工作量参照，但 Codex 主开发模式需要通过 G0/G1 实测吞吐重新估算。
- 每通过一个 Gate 发布一次可运行版本和验收摘要；不等待所有功能完成才首次测试。
- 任何 Gate 可演示不等于可试产；只有自动检查、真机验证、数据/安全检查和回滚证据齐全才可关闭。
